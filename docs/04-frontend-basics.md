## 一、浏览器里同时跑着三种语言

| 语言                 | 管什么                           | 类比       |
| -------------------- | -------------------------------- | ---------- |
| **HTML**       | **结构** —— 页面上有什么 | 骨骼       |
| **CSS**        | **样式** —— 长什么样     | 皮肤、衣服 |
| **JavaScript** | **行为** —— 能做什么     | 肌肉、动作 |

**三者分工，各管一摊。** 这叫"关注点分离"—— 和你在后端学的"路由归路由、校验归校验"是同一个思路。

> ⚠️ **一个常见误解**：HTML 不是"编程语言"。
> 它没有变量、没有循环、没有逻辑，**只是"描述结构"的标记语言**（和 XML 一个家族）。
> **真正干活的是 JavaScript。**

**四个文件各司其职：**

| 文件                 | 角色 |
| -------------------- | ---- |
| `index.html`       | 结构 |
| `style.css`        | 样式 |
| `app.js`           | 行为 |
| `（后端 main.py）` | 数据 |

## 二、HTML：页面是一棵树

### 长什么样

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <title>待办清单</title>
    <link rel="stylesheet" href="style.css">      <!-- 引入 CSS -->
</head>
<body>
    <h1>我的待办</h1>

    <form id="new-form">
        <input id="new-title" type="text" placeholder="要做什么？">
        <button type="submit">添加</button>
    </form>

    <ul id="list"></ul>                            <!-- 空列表，等 JS 填 -->

    <script src="app.js"></script>                 <!-- 引入 JS，放最后 -->
</body>
</html>
```

### 三个基本词

| 词             | 例子                          | 说明                                  |
| -------------- | ----------------------------- | ------------------------------------- |
| **标签** | `<h1>` `</h1>`            | 成对出现（少数自闭合，如`<input>`） |
| **元素** | `<h1>我的待办</h1>`         | 开标签 + 内容 + 闭标签                |
| **属性** | `id="list"` `type="text"` | 写在开标签里的"键=值"                 |

### ⭐ 关键认知：浏览器把 HTML 解析成一棵「DOM 树」

```
document
└── html
    ├── head
    │   ├── meta
    │   ├── title
    │   └── link
    └── body
        ├── h1
        ├── form#new-form
        │   ├── input#new-title
        │   └── button
        ├── ul#list
        └── script
```

**DOM = Document Object Model（文档对象模型）。**

### ⭐⭐ 为什么叫"对象模型" —— 这句话是关键

**树上每一个节点，在内存里都是一个「对象」。**

```javascript
// 有属性（数据）
element.textContent = "写实验报告";   // 改文字
element.className = "done";           // 改 CSS 类
element.dataset.id = "4";             // 存自定义数据

// 有方法（行为）
element.appendChild(child);           // 加子节点
element.remove();                     // 删掉自己
```

**这和你在 Java / C++ 里写的对象是一回事** —— 有字段、有方法。

只是这些对象代表的不是业务数据，而是"**页面上的一块区域**"。

> **换个角度**：DOM 就是一棵**可变的对象树**，你的 JavaScript 拿到的是这棵树的根（`document`），然后顺着它找到任意节点、读它、改它、删它。
> **数据结构课上的树，在这里变成了可以操作的东西。**

### 为什么 `<script>` 要放在 `<body>` 最后

**因为 HTML 是从上往下解析的。**

如果 `<script>` 放在 `<head>` 里，它会**在 `<ul>` 被创建之前**执行 —— 那时 `document.querySelector("#list")` 返回 `null`，你的代码就崩了。

**放在最后 = 保证所有元素都已经存在。**

## 三、CSS：给树上的节点贴样式

### 长什么样

```css
#list {                    /* id 选择器 */
    list-style: none;
    padding: 0;
}

li {                       /* 标签选择器 */
    padding: 8px;
    border-bottom: 1px solid #eee;
}

.done {                    /* 类选择器 */
    text-decoration: line-through;
    color: gray;
}
```

### 三种选择器

| 写法      | 选中什么                    | 优先级 |
| --------- | --------------------------- | ------ |
| `li`    | 所有`<li>` 标签           | 低     |
| `.done` | 所有`class="done"` 的元素 | 中     |
| `#list` | `id="list"` 那一个        | 高     |

> **类（class）可以很多元素共用；id 在一个页面里应该唯一。**
> 所以**样式一般用类，不用 id** —— id 留给 JavaScript 定位。

### ⭐ 盒模型：CSS 最容易懵的地方

```
┌─────────── margin（外边距，盒子之间的距离）───────────┐
│  ┌───────── border（边框）───────────────────────┐  │
│  │  ┌────── padding（内边距，内容和边框的距离）──┐ │  │
│  │  │                                          │ │  │
│  │  │        content（真正的内容）              │ │  │
│  │  │                                          │ │  │
│  │  └──────────────────────────────────────────┘ │  │
│  └───────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────┘
```

| 属性        | 含义                                           |
| ----------- | ---------------------------------------------- |
| `padding` | 盒子**里面**的填充（内容离自己边框多远） |
| `margin`  | 盒子**外面**的间隔（自己离别人多远）     |
| `border`  | 边框本身                                       |

### 布局：Flex

现代 CSS 布局主要用 **Flex**（弹性盒子）：

```css
li {
    display: flex;
    justify-content: space-between;   /* 两端对齐 */
    align-items: center;              /* 垂直居中 */
}
```

**待办清单用这两个属性就够了。**

### ⭐ 关键认知：CSS 也是「声明式」的

```css
.done { text-decoration: line-through; }
```

**你说的是"class 为 done 的东西，文字要有删除线"**，而不是"怎么算出这条线画在哪、多长"。

> **又是命令式 vs 声明式的对比** —— 你在 SQL 里见过一次，**马上要在 React 里再见一次**。

## 四、JavaScript：和 Python 对比着看

你已经会 Python，所以最快的路是"对照表"。

| 概念       | Python                 | JavaScript                       |
| ---------- | ---------------------- | -------------------------------- |
| 变量       | `x = 1`              | `let x = 1` / `const x = 1`  |
| 函数       | `def f(a): return a` | `function f(a) { return a }`   |
| 箭头函数   | `lambda x: x + 1`    | `(x) => x + 1`                 |
| 条件       | `if a == b:`         | `if (a === b) { }`             |
| 循环       | `for x in xs:`       | `for (const x of xs) { }`      |
| 列表       | `[1, 2, 3]`          | `[1, 2, 3]`                    |
| 字典       | `{"a": 1}`           | `{"a": 1}` ← 叫**对象** |
| 取属性     | `d["a"]`             | `obj.a`（也可 `obj["a"]`）   |
| 空值       | `None`               | `null` / `undefined`         |
| 布尔       | `True` / `False`   | `true` / `false`             |
| 字符串拼接 | `f"{a}{b}"`          | `` `${a}${b}` ``                 |
| 相等       | `==`                 | **`===`（推荐）**        |

### ⚠️ 四个必须记住的坑

#### ① 用 `===` 不要用 `==`

**JavaScript 的 `==` 会做隐式类型转换**，规则非常绕：

```javascript
1 == "1"            // true    ← 数字和字符串居然相等
0 == false          // true
"" == false         // true
null == undefined   // true
```

**`===` 是严格相等（类型也必须一样）：**

```javascript
1 === "1"           // false   ✅ 符合直觉
0 === false         // false
```

> ⭐ **这正是「三个设计问题」Q2 里讨论过的那件事。**
> 你当时问"为什么 API 不返回 `1/0`"，答案是"JS 里 `0 === false` 是 `false`"。
> **现在你知道 JS 为什么有这种坑了**：因为它的 `==` 太宽松，所以社区约定**一律用 `===`**。

#### ② 变量声明用 `const` 和 `let`，别用 `var`

| 关键字    | 含义                                       |
| --------- | ------------------------------------------ |
| `const` | **不能重新赋值**（默认用这个）       |
| `let`   | 可以重新赋值                               |
| `var`   | **老写法，不要用**（作用域规则有坑） |

#### ③ `null` 和 `undefined` 是两个东西

|               | 含义                                                     |
| ------------- | -------------------------------------------------------- |
| `undefined` | "**还没有值**"（声明了但没赋值、对象没有这个属性） |
| `null`      | "**明确地表示空**"（你自己赋的空值）               |

**调试时这个区分很有用**：报 `undefined` 通常意味着"你访问了一个不存在的东西"。

#### ④ 分号可以省，但建议写

JS 有"自动分号插入"，**大多数情况能猜对，少数情况猜错**。**老实写分号**，省得调试玄学 bug。

## 五、DOM 操作：4A 的核心，也是"痛"的来源

**JavaScript 在浏览器里的主要使命就两件：① 操作 DOM；② 发网络请求。**

### 五个最常用的操作

```javascript
// ① 找到节点
const list = document.querySelector("#list");

// ② 创建一个新节点
const li = document.createElement("li");
li.textContent = "写实验报告";         // 填文字

// ③ 插进页面
list.appendChild(li);

// ④ 改一个节点的内容
li.textContent = "写实验报告 v2";

// ⑤ 删掉一个节点
li.remove();
```

**"把一条任务加到列表里"，就是上面 ①②③ 三步。**

### ⭐⭐ 现在看这个"痛" —— 4A 最重要的收获

**你的程序里有两份"状态"必须保持一致：**

```
        数据（JS 数组）                    界面（DOM 树）
   ["写报告", "跑 30 分钟"]      ←→      <li>写报告</li>
                                          <li>跑 30 分钟</li>
```

**这两份东西必须永远一样，而"保持一致"完全由你负责。**

| 发生了什么                    | 你必须做的事                                       |
| ----------------------------- | -------------------------------------------------- |
| 数据变了（从 API 拉到新数据） | **手动**找到相关节点，改它们                 |
| 用户点了删除                  | **手动**从数组删，**再手动**从页面删   |
| 用户点了打勾                  | **手动**改 class，**手动**改数组里的值 |

**随着功能变多，这个"手动同步"会迅速变成灾难：**

```
忘了同步某一个地方 → 界面显示的和真实数据不一致 → 极难排查的 bug
```

> ⭐ **记住这个痛。这就是 React 存在的全部理由。**
>
> React 对这个问题的回答是：
> **"你别管怎么改界面了。你只描述『数据是这样时，界面应该长什么样』，我来负责让它变成那样。"**
>
> **等你亲手写过 4A，再听到这句话，你会立刻明白它有多香。**

## 六、事件：用户操作怎么触发你的代码

```javascript
document.querySelector("#new-form").addEventListener("submit", (event) => {
    event.preventDefault();              // ← 见下面解释
    const input = document.querySelector("#new-title");
    console.log("用户想添加：", input.value);
});
```

### 两个要点

**① `addEventListener(事件名, 函数)` = "注册一个回调"**

常用事件：`click`（点击）、`submit`（表单提交）、`input`（输入变化）

**② `event.preventDefault()` —— 阻止浏览器的默认行为**

**表单的默认行为是"提交并刷新整个页面"。** 如果不阻止，页面一刷新，**JS 里所有状态全丢**。

> ⚠️ **这是前端新手必踩的坑**：不加这一行，你会看到"刚添加的任务闪了一下就没了"。

### ⭐ 眼熟吗？这和 FastAPI 的装饰器是同一件事

**FastAPI（你已经会的）：**

```python
@app.get("/todos")               # 注册：路径 → 函数
def read_todos():
    ...
```

**JavaScript（现在学的）：**

```javascript
button.addEventListener("click", fn)    # 注册：事件 → 函数
```

|                      | 注册什么                      | 谁来触发                  |
| -------------------- | ----------------------------- | ------------------------- |
| FastAPI 装饰器       | **路径 + 方法 → 函数** | **HTTP 请求到来**   |
| `addEventListener` | **事件类型 → 函数**    | **用户的点击/输入** |

**完全同构。**

> 这就是"**装饰器的本质是往一张表里注册**"这个认知的用处 ——
> **同一个模式，你在 HTTP 里见过一次，在前端里又见一次。**
> 这不是巧合：一切"事件驱动"的系统都是这个结构（操作系统的中断向量表也一样）。

## 七、`fetch`：调用后端 API

```javascript
// ✅ 现代写法（推荐）
async function loadTodos() {
    const res = await fetch("http://127.0.0.1:8000/todos");
    const todos = await res.json();          // 把响应体解析成 JS 对象
    console.log(todos);
}
```

### ⚠️ 两个 `await`，别漏第二个

```javascript
const res  = await fetch(url);        // ① 等"响应头"到达
const data = await res.json();        // ② 等"响应体"读完并解析
```

**`fetch` 返回的不是数据，是一个 `Promise`**（"承诺稍后给你结果"）。

### 为什么是异步的？

**因为网络很慢**（几百毫秒），而**浏览器只有一个线程**。

如果 `fetch` 是同步的：

```
你的代码在等网络 → 浏览器什么都干不了 → 界面冻结、按钮点不动、鼠标转圈
```

**所以 JS 的设计是："先去做，做完了通知我。"** 这就是 `Promise` / `async` / `await`。

### 🔗 和 Python 对比

|          | Python                                   | JavaScript                                |
| -------- | ---------------------------------------- | ----------------------------------------- |
| 请求 API | `requests.get(url)` **同步阻塞** | `fetch(url)` **异步返回 Promise** |
| 想并发   | 要用多线程 /`asyncio`                  | **天生异步**                        |

**为什么不一样？** 因为 Python 里你可以开多线程，而**浏览器里操作 DOM 的只有一个线程**（两个线程同时改页面会乱套）。所以浏览器把"慢操作"（网络、定时器）全部异步化。

> **这一点以后很重要**：阶段 8 调大模型 API 也是几百毫秒到几秒，**那时你会用到 Python 的 `async`** —— 和这里的 `async/await` 是同一套思想。

## 八、CORS：你马上会撞上的墙

### 什么是"同源"

**协议 + 域名 + 端口，三者完全相同**才算同源。

| 对比                                                             | 同源？ | 原因                             |
| ---------------------------------------------------------------- | ------ | -------------------------------- |
| `http://127.0.0.1:8000` vs `http://127.0.0.1:8000`           | ✅     | 全同                             |
| `http://127.0.0.1:8000` vs **`http://127.0.0.1:5500`** | ❌     | **端口不同** ← 你会撞上的 |
| `http://a.com` vs `https://a.com`                            | ❌     | 协议不同                         |
| **`http://localhost:5500` vs `http://127.0.0.1:8000`** | ❌     | **主机名不同！**           |

> ⚠️ **最后一行是个经典陷阱**：`localhost` 和 `127.0.0.1` 指向同一台机器，但**浏览器认为它们是不同的源**。
> **所以前后端要统一用 `127.0.0.1`（或统一用 `localhost`），不要混。**

### 浏览器为什么要拦

**防止恶意网站偷你的数据。**

设想：你登录了网银 `bank.com`，浏览器里存着你的 cookie。这时你打开恶意网站 `evil.com`，它的 JS 偷偷发请求到 `bank.com`……

**如果没有同源策略，`evil.com` 就能带着你的 cookie 读你的账户余额。**

**同源策略就是拦这个的。**

### ⭐ 谁拦的：**浏览器**，不是服务器

**这是理解 CORS 的关键。**

| 工具                | 会被拦吗             | 为什么                        |
| ------------------- | -------------------- | ----------------------------- |
| `curl`            | ❌**不会被拦** | curl 不是浏览器，没有同源策略 |
| 浏览器里的`fetch` | ✅**会被拦**   | 浏览器强制执行同源策略        |

> **你其实早就见过这个现象**：
> 笔记里写过 —— *"跨域报错时会发现'用 curl 能通、用浏览器就不行'。"*
> **现在你会亲眼验证它。**

### 顺带：你会看到神秘的 `OPTIONS` 请求

带 `Content-Type: application/json` 的 POST 属于"**非简单请求**"，浏览器会**先发一个 `OPTIONS` 请求问一句**：

```
OPTIONS /todos
Origin: http://127.0.0.1:5500
```

这叫**预检请求（preflight）**："我来自 5500 端口，想给你发个 JSON POST，你允许吗？"

服务器答"允许"，浏览器才发真正的 POST。**所以 F12 的 Network 里你会看到两条请求** —— 别慌，这是正常的。

### 怎么修：服务器加几行配置

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://127.0.0.1:5500"],   # 允许这个源
    allow_methods=["*"],
    allow_headers=["*"],
)
```

**本质就是：让服务器在响应里加一个头** `Access-Control-Allow-Origin: http://127.0.0.1:5500`，告诉浏览器"我允许它跨域访问我"。

> **注意**：同源策略是**浏览器**的限制，所以"解法"也只能是**服务器同意**。
> **这就是为什么必须改后端** —— 前端改什么都没用。

## 九、把 4A 串起来：一次点击的完整旅程

```
① 用户在输入框打字，点"添加"
        │
        ▼
② 浏览器触发 submit 事件
        │
        ▼
③ 你注册的回调函数被执行            ← addEventListener
        │
        ▼
④ 你的 JS 用 fetch 发 POST 到后端    ← 跨域！浏览器会先问 OPTIONS
        │
        ▼
⑤ ┌─────────────────────────────────┐
   │  你的 FastAPI 后端               │  ← ⭐ 这一步你早就写好了
   │  校验 → 写数据库 → 返回 JSON     │
   └─────────────────────────────────┘
        │
        ▼
⑥ fetch 的 Promise resolve，你拿到数据
        │
        ▼
⑦ 你的 JS 用 DOM 操作把新任务加到页面上   ← 手动同步！(4A 的痛)
        │
        ▼
⑧ 用户看到新任务出现在列表里
```

## 十、速查表

### HTML 常用标签

| 标签                        | 用途                                            |
| --------------------------- | ----------------------------------------------- |
| `<h1>` ~ `<h6>`         | 标题                                            |
| `<p>`                     | 段落                                            |
| `<ul>` / `<li>`         | 无序列表 / 列表项                               |
| `<form>`                  | 表单（能触发`submit`）                        |
| `<input>`                 | 输入框（`type="text"` / `type="checkbox"`） |
| `<button>`                | 按钮（`type="submit"` / `type="button"`）   |
| `<div>` / `<span>`      | 通用容器（块级 / 行内）                         |
| `<link rel="stylesheet">` | 引入 CSS（放`<head>`）                        |
| `<script src="...">`      | 引入 JS（放`<body>` **最后**）          |

### CSS 常用

| 属性                                  | 作用                   |
| ------------------------------------- | ---------------------- |
| `padding` / `margin`              | 内边距 / 外边距        |
| `border`                            | 边框                   |
| `color` / `background`            | 文字色 / 背景          |
| `display: flex`                     | 弹性布局               |
| `justify-content` / `align-items` | 主轴对齐 / 交叉轴对齐  |
| `text-decoration: line-through`     | 删除线（标记"已完成"） |

### DOM 五件事

```javascript
document.querySelector("#list")        // 找节点
document.createElement("li")            // 造节点
element.textContent = "..."             // 改文字
parent.appendChild(child)               // 插进去
element.remove()                        // 删掉
element.classList.add("done")           // 加 CSS 类
element.dataset.id = "4"                // 存自定义数据
```

### fetch 模板

```javascript
// GET
const res = await fetch(url);
const data = await res.json();

// POST
const res = await fetch(url, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ title: "新任务", done: false }),
});
const data = await res.json();
```

> ⚠️ **`JSON.stringify(...)` 不能少** —— `body` 要的是**字符串**，不是 JS 对象。
> （对比：后端收到后用 Pydantic 解析成对象。**一个序列化、一个反序列化。**）

### CORS 配置（FastAPI）

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://127.0.0.1:5500"],
    allow_methods=["*"],
    allow_headers=["*"],
)
```
